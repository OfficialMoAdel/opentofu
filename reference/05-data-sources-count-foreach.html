📖 مصادر البيانات (Data Sources)

تُستخدم لقراءة معلومات من موارد موجودة مسبقاً (لم تُنشأ بواسطة هذا الـ Configuration).

📄 الصيغة العامة

data "<data_type>" "<data_name>" {
  # arguments لتحديد المورد
}

📄 مثال: قراءة Key Pair موجود

# data block لقراءة مفتاح موجود
data "aws_key_pair" "cerberus-key" {
  key_name = "alpha"
}

# استخدام الـ data في مورد جديد
resource "aws_instance" "cerberus" {
  ami           = var.ami
  instance_type = var.instance_type
  key_name      = data.aws_key_pair.cerberus-key.key_name  # ← Reference
}

📄 مثال: استخدام الفلاتر (Filters)

# البحث عن مفتاح عبر الـ tags
data "aws_key_pair" "cerberus-key" {
  filter {
    name   = "tag:project"
    values = ["cerberus"]
  }
}

📄 مثال: قراءة ملف محلي

# قراءة ملف موجود
data "local_file" "os" {
  filename = "/etc/os-release"
}

# عرض المحتوى عبر output
output "os_version" {
  value = data.local_file.os.content
}

✅ صيغة الـ Reference للـ Data Source

# الصيغة العامة
data.data_type.data_name.attribute

# مثال عملي
data.aws_key_pair.cerberus-key.key_name

💡 الفرق بين Resource و Data Source

المعيار Resource Data Source
الكلمة المفتاحية resource data
الوظيفة إنشاء، تعديل، حذف قراءة فقط
الإدارة مُدار بواسطة OpenTofu غير مُدار (موجود مسبقاً)
الـ Reference type.name.attr data.type.name.attr

🔢 الوسائط الوصفية: count

يُستخدم لإنشاء عدة موارد من نفس الـ resource block. الموارد تُنشأ كـ قائمة (list) مع فهرس (index) يبدأ من 0.

📄 مثال أساسي

# إنشاء 3 ماكينات EC2
resource "aws_instance" "web" {
  ami           = var.ami
  instance_type = var.instance_type
  count         = 3
}

📄 استخدام count.index مع قائمة

# variables.tf
variable "webservers" {
  type    = list(string)
  default = ["web1", "web2", "web3"]
}

# main.tf
resource "aws_instance" "web" {
  ami           = var.ami
  instance_type = var.instance_type
  count         = length(var.webservers)  # ← استخدام طول القائمة

  tags = {
    Name = var.webservers[count.index]  # ← count.index
  }
}

🔍 النتيجة في الـ State

tofu state list
# النتيجة:
# aws_instance.web[0]  ← web1
# aws_instance.web[1]  ← web2
# aws_instance.web[2]  ← web3

❌ مشكلة count: الإزاحة (Index Shift)

عند حذف عنصر من بداية القائمة، تتغير الفهارس لجميع العناصر التالية!

مثال:

قبل الحذف

[0]=web1, [1]=web2, [2]=web3

بعد حذف web1

[0]=web2 ← سيتم تحديثه!
[1]=web3 ← سيتم تحديثه!
[2]=محذوف ← سيتم حذفه!

النتيجة: 2 تحديث + 1 حذف بدلاً من حذف واحد فقط!

🔄 الوسائط الوصفية: for_each

يُستخدم لإنشاء عدة موارد من نفس الـ resource block. الموارد تُنشأ كـ خريطة (map) بدلاً من قائمة.

📄 مثال أساسي

# variables.tf - يجب أن يكون set وليس list
variable "webservers" {
  type    = set(string)  # ← set وليس list!
  default = ["web1", "web2", "web3"]
}

# main.tf
resource "aws_instance" "web" {
  ami           = var.ami
  instance_type = var.instance_type
  for_each      = var.webservers

  tags = {
    Name = each.value  # ← each.value
  }
}

📄 استخدام toset() مع قائمة

# إذا كان المتغير list، يمكن تحويله إلى set
resource "local_sensitive_file" "name" {
  filename = each.value
  content  = var.content
  for_each = toset(var.users)  # ← تحويل list إلى set
}

📄 مثال مع map

# variables.tf
variable "servers" {
  type = map(string)
  default = {
    "web"  = "t2.micro"
    "db"   = "m5.large"
    "cache" = "t3.small"
  }
}

# main.tf
resource "aws_instance" "servers" {
  ami           = var.ami
  instance_type = each.value
  for_each      = var.servers

  tags = {
    Name = each.key  # ← each.key
  }
}

🔍 النتيجة في الـ State

tofu state list
# النتيجة:
# aws_instance.web["web1"]  ← خريطة وليس قائمة
# aws_instance.web["web2"]
# aws_instance.web["web3"]

✅ ميزة for_each: لا يوجد مشكلة الإزاحة

عند حذف عنصر، يتم حذف العنصر المحدد فقط دون التأثير على الآخرين!

بعد حذف web1

["web1"]=محذوف فقط ✅
["web2"]=بدون تغيير ✅
["web3"]=بدون تغيير ✅

⚖️ مقارنة: count مقابل for_each

count

  • ✅ بسيط وسهل للفهم
  • ✅ مناسب للأعداد الثابتة
  • ❌ الموارد تُنشأ كـ قائمة
  • ❌ مشكلة الإزاحة عند الحذف
  • ❌ لا يمكن استخدام قيم فريدة كمفتاح
  • 📌 الصيغة: resource[0], resource[1]

for_each

  • ✅ الموارد تُنشأ كـ خريطة
  • ✅ لا مشكلة إزاحة عند الحذف
  • ✅ كل مورد له مفتاح فريد
  • ❌ يتطلب set أو map
  • ❌ لا يقبل list مباشرة (يحتاج toset())
  • 📌 الصيغة: resource["key"]
المعيار count for_each
نوع المتغير number أو list set أو map
المتغير الخاص count.index each.key, each.value
التمثيل في الـ State قائمة: [0], [1], [2] خريطة: ["key1"], ["key2"]
عند حذف عنصر ⚠️ قد يتم تحديث موارد أخرى ✅ يُحذف العنصر المحدد فقط
متى تستخدمه؟ أعداد ثابتة، عناصر متطابقة قيم فريدة، إدارة ديناميكية

🎤 سؤال مقابلة شائع جداً

ما الفرق بين count و for_each؟ ولماذا تفضل for_each في معظم الحالات؟

count يُنشئ الموارد كقائمة مع فهارس رقمية. عند حذف عنصر من المنتصف أو البداية، تتغير فهارس جميع العناصر التالية مما قد يؤدي إلى إعادة إنشاء موارد غير مرتبطة.

for_each يُنشئ الموارد كخريطة مع مفاتيح فريدة. عند حذف عنصر، يُحذف فقط العنصر المحدد بمفتاحه دون التأثير على الآخرين.

لذلك، for_each أكثر أماناً للإدارة الديناميكية.

🎯 أمثلة عملية من الملف

📄 مثال 1: إنشاء ملفات محلية مع count

# variables.tf
variable "users" {
  type = list(string)
  default = ["/root/user1", "/root/user2", "/root/user3"]
}

variable "content" {
  default = "password: S3cr3tP@ssw0rd"
}

# main.tf
resource "local_sensitive_file" "name" {
  filename = var.users[count.index]
  content  = var.content
  count    = length(var.users)
}

📄 مثال 2: إنشاء ملفات مع for_each

# main.tf
resource "local_sensitive_file" "name" {
  filename = each.value
  content  = var.content
  for_each = toset(var.users)  # ← تحويل إلى set
}

📄 مثال 3: إنشاء عدة موارد مع نفس الإعداد

# إنشاء 3 ملفات بنفس المحتوى
resource "local_sensitive_file" "name" {
  filename = "/root/file.txt"
  content  = "Hello World"
  count    = 3
}

# النتيجة: 3 ملفات بنفس الاسم!
# ملاحظة: هذا قد يسبب مشكلة لأن الملفات لها نفس الاسم

⚠️ أخطاء شائعة يجب تجنبها

❌ خطأ 1: استخدام list مع for_each

# ❌ خطأ - for_each لا يقبل list
for_each = var.users  # إذا كان users من نوع list

# ✅ صحيح - تحويل إلى set أولاً
for_each = toset(var.users)

❌ خطأ 2: نسيان القوس المربع مع count.index

# ❌ خطأ
Name = var.webservers.count.index

# ✅ صحيح
Name = var.webservers[count.index]

❌ خطأ 3: استخدام count مع قيم فريدة

إذا كانت القائمة تحتوي على قيم فريدة (مثل أسماء السيرفرات)، استخدم for_each بدلاً من count لتجنب مشكلة الإزاحة.

❌ خطأ 4: تكرار نفس الاسم في الملفات مع count

عند استخدام count لإنشاء ملفات محلية، تأكد من أن كل ملف له اسم فريد. وإلا سيتم إنشاء ملف واحد فقط!

🎤 أسئلة مقابلات مهمة

سؤال 1: ما الفرق بين Resource و Data Source؟

Resource: يُستخدم لإنشاء وتعديل وحذف البنية التحتية (مُدار بواسطة OpenTofu).
Data Source: يُستخدم فقط لقراءة معلومات من موارد موجودة مسبقاً (غير مُدار).

سؤال 2: ما هي صيغة الـ Reference لـ Data Source؟

data.data_type.data_name.attribute
مثال: data.aws_key_pair.cerberus-key.key_name

سؤال 3: لماذا for_each أفضل من count في معظم الحالات؟

لأن count يُنشئ الموارد كقائمة مع فهارس رقمية. عند حذف عنصر، تتغير فهارس جميع العناصر التالية مما قد يؤدي إلى إعادة إنشاء موارد غير مرتبطة.
بينما for_each يُنشئ الموارد كخريطة مع مفاتيح فريدة، مما يجعل الحذف أكثر دقة.

سؤال 4: ما هي أنواع البيانات التي يمكن استخدامها مع for_each؟

set أو map فقط. لا يمكن استخدام list مباشرة (يجب تحويله إلى set أولاً باستخدام toset()).

سؤال 5: ما الفرق بين each.key و each.value؟

each.key: المفتاح في الخريطة (أو القيمة في الـ set).
each.value: القيمة المرتبطة بالمفتاح في الخريطة (أو القيمة في الـ set).

في حالة الـ set، each.key و each.value يكونان نفس القيمة.
