🔴 الـ Tainting (الموارد الملوثة)

عندما يفشل إنشاء مورد لأي سبب (مثل فشل الـ provisioner)، يقوم OpenTofu بتعليم المورد كـ tainted. في الـ apply التالي، سيتم إعادة إنشاء المورد بالكامل.

📄 مثال: فشل الـ provisioner

resource "aws_instance" "webserver" {
  ami           = "ami-0edab43b6fa892279"
  instance_type = "t2.micro"

  # ← provisioner بمسار خاطئ
  provisioner "local-exec" {
    command = "echo ${aws_instance.webserver.public_ip} >> /invalid/path/ips.txt"
    #                                          ↑ مسار غير موجود!
  }
}

🔍 النتيجة عند فشل الـ apply

tofu apply

Error: local-exec provisioner error
  with aws_instance.webserver,
  on main.tf line 8, in resource "aws_instance" "webserver":
  8:   provisioner "local-exec" {

# المورد تم إنشاؤه لكن الـ provisioner فشل
# → المورد أصبح tainted

🔍 عند تشغيل tofu plan مرة أخرى

tofu plan

# aws_instance.webserver is tainted, so must be replaced
-/+ resource "aws_instance" "webserver" {
      # ... سيتم إعادة إنشاء المورد بالكامل
}

Plan: 1 to add, 0 to change, 1 to destroy.

⚠️ نقطة مهمة

حتى لو كان المورد نفسه (مثل EC2 instance) تم إنشاؤه بنجاح، إذا فشل أي خطوة لاحقة (مثل الـ provisioner)، يتم تعليم المورد كـ tainted وسيتم إعادة إنشائه بالكامل في الـ apply التالي!

🔄 الإجبار على إعادة الإنشاء: --replace و untaint

يمكنك إجبار إعادة إنشاء مورد معين، أو إلغاء الـ taint إذا تم إصلاح المشكلة.

📄 tofu apply -replace

يُستخدم لإجبار إعادة إنشاء مورد معين. هذا هو البديل الحديث لـ tofu taint (الذي أصبح deprecated). 

# إجبار إعادة إنشاء مورد معين
tofu apply -replace=aws_instance.project_b

# الصيغة العامة
tofu apply -replace=resourceType.resourceName

💡 متى تستخدم -replace؟

  • عندما يتم تعديل المورد يدوياً خارج OpenTofu
  • عندما تريد إعادة إنشاء مورد بدون حذفه أولاً
  • عندما يكون المورد في حالة غير متسقة

📄 tofu untaint

يُستخدم لإلغاء الـ taint عن مورد، بحيث لا يتم إعادة إنشائه في الـ apply التالي. 

# إلغاء الـ taint عن مورد
tofu untaint aws_instance.webserver

# الآن لن يتم إعادة إنشاء المورد في الـ apply التالي
tainted

المورد فشل وسيُعاد إنشاؤه

→
tofu untaint

إلغاء الـ taint

→
normal

المورد لن يُعاد إنشاؤه

الأمر الوظيفة متى تستخدمه
tofu taint تعليم مورد كـ tainted (قديم) ⚠️ deprecated - لا تستخدمه
tofu apply -replace إجبار إعادة إنشاء مورد ✅ البديل الحديث
tofu untaint إلغاء الـ taint عند إصلاح المشكلة يدوياً

📥 الـ Import (استيراد الموارد)

يُستخدم لجلب موارد موجودة مسبقاً (أُنشئت يدوياً أو بأدوات أخرى) إلى إدارة OpenTofu.

📄 الطريقة 1: tofu import command

# الخطوة 1: إنشاء resource block فارغ
resource "aws_instance" "webserver2" {
  # ← فارغ، سيتم ملؤه بعد الاستيراد
}

# الخطوة 2: تشغيل أمر الاستيراد
tofu import aws_instance.webserver2 i-0123456789abcdef0
#              ↑                          ↑
#              عنوان المورد              المعرف الفريد (من الـ Console)

# النتيجة: المورد أصبح في الـ state

⚠️ تنبيه مهم

tofu import لا يحدّث ملفات الإعداد! يجب عليك يدوياً ملء الـ resource block بجميع السمات (مثل ami, instance_type, tags).

📄 الطريقة 2: import block (الطريقة الجديدة)

# import block
import {
  to = aws_instance.webserver2
  id = "i-0123456789abcdef0"
}

# resource block (يجب أن يطابق العنوان في الـ import)
resource "aws_instance" "webserver2" {
  ami           = "ami-0c9bfc21ac5bf10eb"
  instance_type = "t2.large"
  tags = {
    Name = "webserver2"
  }
}

💡 الفرق بين الطريقتين

المعيار tofu import import block
متى يعمل؟ عند تشغيل الأمر يدوياً أثناء plan و apply
يمكن إزالته؟ غير قابل للإزالة (أمر فقط) يمكن إزالته بعد الاستيراد
التوثيق لا يترك أثراً يبقى كسجل في الكود

📄 مثال عملي كامل

# 1. إنشاء resource block فارغ
resource "aws_instance" "jade-mw" {
  # فارغ
}

# 2. تشغيل الاستيراد
tofu import aws_instance.jade-mw i-47a8764efa9248c14

# 3. ملء الـ resource block من الـ state
resource "aws_instance" "jade-mw" {
  ami           = "ami-082b3eca746b12a89"
  instance_type = "t2.large"
  key_name      = "jade"
  tags = {
    Name = "jade-mw"
  }
}

# 4. التحقق من أن كل شيء متطابق
tofu plan
# يجب أن يعرض: No changes

🐛 الـ Debugging (التصحيح)

OpenTofu يوفر نظام logging قوي يساعد في اكتشاف الأخطاء. يتم تفعيله عبر متغيرات البيئة.

📄 تفعيل الـ Logging

# Linux/Mac
export TF_LOG="DEBUG"
tofu apply

# أو مع تحديد مسار الـ log
export TF_LOG="ERROR"
export TF_LOG_PATH="/tmp/opentofu.log"
tofu apply

# Windows (PowerShell)
$env:TF_LOG = "DEBUG"
$env:TF_LOG_PATH = "C:\temp\opentofu.log"
tofu apply

📊 مستويات الـ Logging

TRACE ← الأكثر تفصيلاً، يعرض كل شيء
DEBUG ← معلومات تصحيح مفصلة
INFO ← معلومات عامة عن العملية
WARN ← تحذيرات فقط
ERROR ← الأخطاء فقط (الأقل تفصيلاً)

⚠️ تنبيه مهم

تحديد TF_LOG_PATH فقط لا يكفي! يجب أيضاً تحديد TF_LOG مع مستوى الـ logging. وإلا لن يتم إنشاء ملف الـ log.

📄 مثال عملي كامل

# تفعيل الـ logging بمستوى ERROR مع حفظه في ملف
export TF_LOG="ERROR"
export TF_LOG_PATH="/tmp/project_a.log"

# تشغيل الأوامر
tofu init
tofu apply

# عرض الـ log
cat /tmp/project_a.log

# النتيجة:
2025-06-21T12:30:15.123+0200 [ERROR] aws_instance.ProjectA: Creating...
2025-06-21T12:30:16.456+0200 [ERROR] Error: AuthFailure: ...

💡 نصيحة للمقابلات

أي مستوى من الـ logging يعرض أكثر التفاصيل؟
الإجابة: TRACE - يعرض جميع المعلومات بما في ذلك الطلبات والاستجابات الكاملة.

🎯 مثال عملي كامل: استكشاف الأخطاء وإصلاحها

📄 السيناريو: مورد tainted

# 1. تشغيل apply وفشل الـ provisioner
tofu apply
# Error: local-exec provisioner error
# → المورد أصبح tainted

# 2. تشغيل plan لرؤية الـ taint
tofu plan
# aws_instance.ProjectB is tainted, so must be replaced

# 3. إصلاح المشكلة في الكود
# (مثلاً: تصحيح مسار الـ provisioner)

# 4. إعادة إنشاء المورد
tofu apply -replace=aws_instance.ProjectB

# أو إذا أردت إلغاء الـ taint فقط
tofu untaint aws_instance.ProjectB

📄 السيناريو: استيراد مورد موجود

# 1. إيجاد معرف المورد من الـ Console
# Instance ID: i-47a8764efa9248c14

# 2. إنشاء resource block فارغ
resource "aws_instance" "existing-server" {
}

# 3. استيراد المورد
tofu import aws_instance.existing-server i-47a8764efa9248c14

# 4. عرض الـ state للحصول على جميع السمات
tofu show

# 5. ملء الـ resource block بالسمات
resource "aws_instance" "existing-server" {
  ami           = "ami-0c9bfc21ac5bf10eb"
  instance_type = "t2.large"
  tags = {
    Name = "existing-server"
  }
}

# 6. التحقق
tofu plan
# No changes. Your infrastructure matches the configuration.

⚠️ أخطاء شائعة يجب تجنبها

❌ خطأ 1: استخدام tofu taint (deprecated)

# ❌ قديم - لا تستخدمه
tofu taint aws_instance.webserver

# ✅ البديل الحديث
tofu apply -replace=aws_instance.webserver

❌ خطأ 2: نسيان ملء الـ resource block بعد الاستيراد

tofu import يضيف المورد إلى الـ state فقط. يجب يدوياً ملء الـ resource block بجميع السمات. وإلا سيعطي tofu apply خطأ!

❌ خطأ 3: تحديد TF_LOG_PATH بدون TF_LOG 

# ❌ خطأ - لن يتم إنشاء ملف الـ log
export TF_LOG_PATH="/tmp/debug.log"

# ✅ صحيح - يجب تحديد كلا المتغيرين
export TF_LOG="DEBUG"
export TF_LOG_PATH="/tmp/debug.log"

❌ خطأ 4: تشغيل tofu untaint بدون إصلاح المشكلة

إذا ألغيت الـ taint دون إصلاح السبب الجذري، سيفشل المورد مرة أخرى في الـ apply التالي وسيصبح tainted مرة أخرى!

🎤 أسئلة مقابلات مهمة

سؤال 1: ما هو الـ Tainting؟

عندما يفشل إنشاء مورد (أو أي خطوة أثناء الإنشاء مثل الـ provisioner)، يتم تعليم المورد كـ tainted. في الـ apply التالي، سيتم إعادة إنشاء المورد بالكامل.

سؤال 2: ما الفرق بين tofu taint و tofu apply -replace؟

tofu taint أصبح deprecated.
البديل الحديث هو tofu apply -replace=resourceType.resourceName الذي يجمع بين الـ taint والـ apply في خطوة واحدة.

سؤال 3: ما هي خطوات استيراد مورد موجود؟

1. إنشاء resource block فارغ في الكود.
2. تشغيل tofu import resourceType.resourceName resource_id.
3. ملء الـ resource block بجميع السمات من الـ tofu show.
4. التحقق عبر tofu plan (يجب أن يعرض No changes).

سؤال 4: كيف تفعّل الـ logging في OpenTofu؟

عبر متغيرات البيئة:
• TF_LOG: مستوى الـ logging (TRACE, DEBUG, INFO, WARN, ERROR)
• TF_LOG_PATH: مسار حفظ الـ log (اختياري)
ملاحظة: يجب تحديد TF_LOG حتى لو حددت TF_LOG_PATH.

سؤال 5: ما الفرق بين tofu import والـ import block؟

tofu import: أمر يُشغل يدوياً مرة واحدة.
import block: يُعالج أثناء plan و apply، ويبقى كسجل في الكود يمكن إزالته لاحقاً.

# ═══════════════════════════════════════════════

# ═══════════════════════════════════════════════

# رؤية الـ taint

# إجبار إعادة الإنشاء (البديل الحديث)
tofu apply -replace=aws_instance.webserver

# إلغاء الـ taint
tofu untaint aws_instance.webserver

# ═══════════════════════════════════════════════
# Import
# ═══════════════════════════════════════════════

# الطريقة 1: الأمر
tofu import aws_instance.name i-1234567890abcdef0

# الطريقة 2: الـ import block
import {
  to = aws_instance.name
  id = "i-1234567890abcdef0"
}

# ═══════════════════════════════════════════════
# Debugging
# ═══════════════════════════════════════════════

# تفعيل الـ logging
export TF_LOG="TRACE"      # الأكثر تفصيلاً
export TF_LOG="DEBUG"      # معلومات تصحيح
export TF_LOG="INFO"       # معلومات عامة
export TF_LOG="WARN"       # تحذيرات فقط
export TF_LOG="ERROR"      # أخطاء فقط

# حفظ الـ log في ملف
export TF_LOG_PATH="/tmp/debug.log"

# ═══════════════════════════════════════════════
# Workflow كامل
# ═══════════════════════════════════════════════

# عند فشل مورد
tofu plan                      # 1. رؤية الـ taint
# إصلاح الكود                  # 2. إصلاح المشكلة
tofu apply -replace=...      # 3. إعادة الإنشاء

# عند استيراد مورد
tofu import ... ...           # 1. الاستيراد
tofu show                     # 2. الحصول على السمات
# ملء الـ resource block       # 3. تحديث الكود
tofu plan                     # 4. التحقق
