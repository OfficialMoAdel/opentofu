🔄 OpenTofu - Dynamic Blocks & Splat Expressions

مرجع شامل للكتل الديناميكية وتعابير الانتشار

📋 نظرة عامة (Overview)

الـ Dynamic Blocks تحل مشكلة تكرار الـ nested blocks (مثل الـ ingress rules في الـ Security Group). الـ Splat Expressions تتيح استخراج سمات من جميع عناصر قائمة.

dynamic

إنشاء nested blocks ديناميكياً

[*]

استخراج سمات من جميع العناصر

Nested Blocks

كتل داخل الـ resource

ℹ️ ما هي الـ Nested Blocks؟

هي كتل تُعرّف داخل الـ resource block. مثال: كتلة ingress داخل aws_security_group. لا يمكن استخدام count أو for_each مباشرة على هذه الكتل، لذلك نحتاج إلى الـ Dynamic Blocks.

❌ المشكلة: تكرار الـ Nested Blocks

لنفترض أننا نريد إنشاء Security Group يسمح بالمنافذ 22 و 8080. بدون الـ Dynamic Blocks، سنحتاج إلى تكرار كتلة الـ ingress.

❌ الطريقة اليدوية (سيئة)

resource "aws_security_group" "backend-sg" {
  name   = "backend-sg"
  vpc_id = aws_vpc.backend-vpc.id

  # ← كتلة مكررة رقم 1
  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # ← كتلة مكررة رقم 2
  ingress {
    from_port   = 8080
    to_port     = 8080
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  # ← إذا أردنا إضافة منفذ 443؟
  # سنحتاج إلى كتلة ثالثة مكررة!
}
  • ❌ كود طويل ومكرر
  • ❌ صعب الصيانة
  • ❌ إضافة منفذ جديد = كتلة جديدة

✅ الطريقة الديناميكية (جيدة)

variable "ingress_ports" {
  type    = list
  default = [22, 8080]
}

resource "aws_security_group" "backend-sg" {
  name   = "backend-sg"
  vpc_id = aws_vpc.backend-vpc.id

  # ← كتلة ديناميكية واحدة!
  dynamic "ingress" {
    for_each = var.ingress_ports

    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}
  • ✅ كود نظيف وقصير
  • ✅ سهل الصيانة
  • ✅ إضافة منفذ = إضافة عنصر للقائمة

🔧 صيغة الـ Dynamic Block

dynamic "BLOCK_NAME" { for_each = COLLECTION content { ... } }
اسم الكتلة
"ingress"
المجموعة للتكرار
var.ingress_ports
محتوى الكتلة
content { ... }

📄 المكونات الأساسية

المكون الوظيفة مثال
dynamic "name" اسم الكتلة التي سيتم تكرارها dynamic "ingress"
for_each المجموعة التي سيتم التكرار عليها for_each = var.ingress_ports
content المحتوى الذي سيتم تكراره content { from_port = ... }
iterator اسم بديل للمتكرر (اختياري) iterator = port

💡 كيف تعمل؟

الـ dynamic block يقوم بالتكرار على كل عنصر في المجموعة، وينشئ نسخة من الـ content لكل عنصر. يمكن الوصول إلى قيمة العنصر الحالي عبر block_name.value.

🎯 مثال عملي كامل: إنشاء VPC مع Security Group

📄 الخطوة 1: إنشاء الـ VPC

resource "aws_vpc" "backend-vpc" {
  cidr_block = "10.0.0.0/16"
  tags = {
    Name = "backend-vpc"
  }
}

📄 الخطوة 2: إنشاء الـ Subnet

resource "aws_subnet" "private-subnet" {
  vpc_id     = aws_vpc.backend-vpc.id  # ← Implicit Dependency
  cidr_block = "10.0.2.0/24"
  tags = {
    Name = "private-subnet"
  }
}

📄 الخطوة 3: إنشاء الـ Security Group مع Dynamic Blocks

# variables.tf
variable "ingress_ports" {
  type    = list
  default = [22, 8080]
}

# main.tf
resource "aws_security_group" "backend-sg" {
  name   = "backend-sg"
  vpc_id = aws_vpc.backend-vpc.id

  # ← Dynamic Block
  dynamic "ingress" {
    for_each = var.ingress_ports

    content {
      from_port   = ingress.value  # ← قيمة العنصر الحالي
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}

🔍 النتيجة

var.ingress_ports

[22, 8080]

→
ingress #1

from_port: 22
to_port: 22

ingress #2

from_port: 8080
to_port: 8080

✅ إضافة منفذ جديد

لإضافة منفذ 443، فقط أضفه إلى القائمة:

variable "ingress_ports" {
  type    = list
  default = [22, 8080, 443]  # ← أضفنا 443
}

لا حاجة لتعديل الـ dynamic block!

🔁 استخدام الـ Iterator (اختياري)

افتراضياً، يمكن الوصول إلى قيمة العنصر عبر اسم الـ dynamic block. يمكن تغيير هذا الاسم باستخدام iterator.

📄 بدون iterator (الافتراضي)

dynamic "ingress" {
  for_each = var.ingress_ports

  content {
    from_port = ingress.value  # ← اسم الـ dynamic block
    to_port   = ingress.value
  }
}

📄 مع iterator

dynamic "ingress" {
  iterator = port  # ← اسم بديل
  for_each = var.ingress_ports

  content {
    from_port = port.value  # ← نستخدم الاسم الجديد
    to_port   = port.value
  }
}

💡 متى تستخدم الـ iterator؟

  • عندما يكون اسم الـ dynamic block طويلاً
  • عندما تريد اسماً أكثر وضوحاً
  • عندما يكون هناك dynamic blocks متداخلة

✨ تعابير الانتشار (Splat Expressions)

تُستخدم لاستخراج سمة من جميع عناصر قائمة. الصيغة تستخدم الرمز [*].

resource.name.attribute[*].sub_attribute
المورد
aws_security_group.backend-sg
رمز الانتشار
[*]
السمة الفرعية
to_port

📄 مثال: استخراج جميع المنافذ

# متغير الإخراج لعرض جميع المنافذ
output "to_ports" {
  value = aws_security_group.backend-sg.ingress[*].to_port
  #                                    ↑              ↑         ↑
  #                                    المورد        الانتشار   السمة
}

🔧 النتيجة

tofu output
# النتيجة:
to_ports = [
  22,
  8080,
]

ℹ️ كيف يعمل الـ Splat؟

الـ ingress rules تُنشأ كـ قائمة داخل الـ aws_security_group. الرمز [*] يخبر OpenTofu بالتكرار على جميع عناصر القائمة واستخراج السمة المحددة من كل عنصر.

🎯 أمثلة إضافية

📄 مثال 1: استخراج عناوين IP من عدة ماكينات

# إنشاء 3 ماكينات باستخدام count
resource "aws_instance" "web" {
  ami           = var.ami
  instance_type = var.instance_type
  count         = 3
}

# استخراج جميع الـ IPs
output "all_ips" {
  value = aws_instance.web[*].public_ip
}

# النتيجة:
all_ips = [
  "54.214.162.160",
  "54.214.162.161",
  "54.214.162.162",
]

📄 مثال 2: استخراج سمات من موارد مع for_each

# ملاحظة: مع for_each، الموارد تُنشأ كـ map وليس list
# لذلك لا يمكن استخدام [*] مباشرة

# بدلاً من ذلك، استخدم:
output "all_ids" {
  value = values(aws_instance.web)[*].id
  #        ↑                              ↑
  #        تحويل الـ map إلى قائمة        الانتشار
}

⚠️ تنبيه مهم

الـ [*] يعمل فقط مع القوائم. إذا كان المورد مُنشأ بـ for_each (كـ map)، يجب أولاً تحويله إلى قائمة باستخدام values().

⚠️ أخطاء شائعة يجب تجنبها

❌ خطأ 1: استخدام count مع الـ nested blocks

# ❌ خطأ - count لا يعمل مع nested blocks
ingress {
  count     = length(var.ports)
  from_port = var.ports[count.index]
  # ...
}

# ✅ صحيح - استخدم dynamic block
dynamic "ingress" {
  for_each = var.ports
  content {
    from_port = ingress.value
    # ...
  }
}

❌ خطأ 2: نسيان الـ content block

# ❌ خطأ - dynamic بدون content لن يعمل
dynamic "ingress" {
  for_each = var.ingress_ports
}

# ✅ صحيح - يجب أن يحتوي على content
dynamic "ingress" {
  for_each = var.ingress_ports
  content {
    from_port = ingress.value
    # ...
  }
}

❌ خطأ 3: استخدام [*] مع موارد for_each 

# ❌ خطأ - for_each ينشئ map وليس list
value = aws_instance.web[*].id

# ✅ صحيح - تحويل الـ map إلى قائمة أولاً
value = values(aws_instance.web)[*].id

🎤 أسئلة مقابلات مهمة

سؤال 1: ما هي الـ Dynamic Blocks ومتى تستخدمها؟

الـ Dynamic Blocks تُستخدم لإنشاء عدة نسخ من الـ _nested blocks ديناميكياً. تُستخدم عندما لا يمكن استخدام count أو for_each مباشرة على الـ _nested block. مثال شائع: إنشاء عدة ingress rules في aws_security_group.

سؤال 2: ما هي صيغة الـ Dynamic Block؟

dynamic "block_name" { for_each = collection content { ... } }
• block_name: اسم الكتلة التي سيتم تكرارها • for_each: المجموعة للتكرار عليها • content: المحتوى الذي سيتم تكراره • يمكن الوصول للقيمة عبر block_name.value

سؤال 3: ما هو الـ Splat Expression؟

تعبير يُستخدم لاستخراج سمة من جميع عناصر قائمة. الصيغة: resource.attribute[*].sub_attribute. مثال: aws_instance.web[*].public_ip يستخرج جميع الـ IPs من قائمة ماكينات.

سؤال 4: ما الفرق بين count و الـ dynamic block؟

count: يُستخدم لإنشاء عدة موارد من نفس الـ resource block.
dynamic: يُستخدم لإنشاء عدة كتل متداخلة (nested blocks) داخل مورد واحد.

سؤال 5: لماذا لا يمكن استخدام [*] مع موارد for_each؟

لأن for_each يُنشئ الموارد كـ خريطة (map) وليس قائمة. الـ [*] يعمل فقط مع القوائم. الحل: استخدام values() لتحويل الـ map إلى قائمة أولاً.
