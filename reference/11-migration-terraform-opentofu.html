🔄 OpenTofu - Migration from Terraform & Rollback

مرجع شامل للترحيل من Terraform إلى OpenTofu والعودة بأمان

📋 نظرة عامة (Overview)

OpenTofu هو فرع مفتوح المصدر من Terraform. الترحيل بينهما سهل نسبياً لأنهما متوافقان حتى الإصدار 1.6. هذا المرجع يشرح خطوات الترحيل والعودة بأمان.

Terraform 1.6 ⇄ OpenTofu 1.6
الإصدار 1.6 من Terraform متوافق تماماً مع OpenTofu 1.6.
إذا كنت تستخدم إصداراً أقدم، قم بالترقية إلى 1.6 أولاً قبل الترحيل.

⚠️ قبل البدء: خطة التعافي من الكوارث

قبل أي ترحيل، تأكد من أن لديك:

  • نسخة احتياطية من ملف الحالة (terraform.tfstate)
  • خطة تعافي واضحة في حالة فشل الترحيل
  • بيئة اختبار لتجربة الترحيل قبل الإنتاج

🚀 خطوات الترحيل إلى OpenTofu

اتبع هذه الخطوات بالترتيب لترحيل آمن من Terraform إلى OpenTofu.

1

إنشاء نسخة احتياطية من ملف الحالة

قم بضغط وأرشفة ملف الحالة قبل أي تغيير.

tar -czf tfstate.tar.gz terraform.tfstate
2

تثبيت OpenTofu

ثبت OpenTofu على جهازك حسب نظام التشغيل.

tofu --version
3

تهيئة المشروع بـ OpenTofu

شغل tofu init لتهيئة المشروع وتنزيل الـ Providers.

tofu init
4

فحص الخطة

شغل tofu plan للتأكد من عدم وجود تغييرات غير متوقعة.

tofu plan
5

اختبار بتغيير صغير

طبق تغييراً صغيراً (مثل تعديل اسم ملف) للتأكد من أن كل شيء يعمل.

tofu apply

✅ نصيحة مهمة

تأكد من أن التغيير الاختباري لا يتضمن أجزاء حرجة من البنية التحتية. استخدم مورداً بسيطاً مثل ملف محلي أو مورد اختباري.

🎯 مثال عملي كامل: الترحيل خطوة بخطوة

📄 الخطوة 1: الإعداد الأولي مع Terraform

# main.tf (قبل الترحيل)
resource "local_file" "config" {
  filename = "terraform.txt"
  content  = "This file has been created with Terraform"
}
# تشغيل الأوامر مع Terraform
terraform init
terraform apply
# → terraform.txt تم إنشاؤه

📄 الخطوة 2: إنشاء نسخة احتياطية

# ضغط ملف الحالة
tar -czf tfstate.tar.gz terraform.tfstate

# التحقق من إنشاء النسخة الاحتياطية
ls -la
# → terraform.tfstate, tfstate.tar.gz

📄 الخطوة 3: تثبيت OpenTofu

# التحقق من نظام التشغيل
cat /etc/os-release
# → Ubuntu 22.04

# تثبيت OpenTofu (مثال على Ubuntu/Debian)
curl -fsSL https://get.opentofu.org/install-opentofu.sh -o install-opentofu.sh
chmod +x install-opentofu.sh
./install-opentofu.sh

# التحقق من التثبيت
tofu --version
OpenTofu v1.6.x

📄 الخطوة 4: التهيئة والفحص

# تهيئة المشروع مع OpenTofu
tofu init

# فحص الخطة - يجب أن يعرض "No changes"
tofu plan
# No changes. Your infrastructure matches the configuration.

📄 الخطوة 5: اختبار بتغيير صغير

# تعديل main.tf
resource "local_file" "config" {
  filename = "opentofu.txt"  # ← تغيير الاسم
  content  = "This file has been created with OpenTofu"
}

# تطبيق التغيير
tofu apply
# → opentofu.txt تم إنشاؤه، و terraform.txt تم حذفه

↩️ الترحيل العكسي: العودة إلى Terraform

إذا واجهت مشاكل مع OpenTofu، يمكنك العودة إلى Terraform بنفس السهولة.

1

إنشاء نسخة احتياطية من حالة OpenTofu

قبل العودة، احفظ الحالة الحالية.

tar -czf terraform.tfstate.tar.gz terraform.tfstate
2

تهيئة المشروع مع Terraform

شغل terraform init لإعادة التهيئة.

terraform init
3

فحص الخطة

تأكد من عدم وجود تغييرات غير متوقعة.

terraform plan
4

الاستمرار مع Terraform

إذا نجحت الخطة، يمكنك الاستمرار بأمان.

terraform apply

📄 مثال عملي: العودة إلى Terraform

# 1. إنشاء نسخة احتياطية
tar -czf terraform.tfstate.tar.gz terraform.tfstate

# 2. إعادة التهيئة مع Terraform
terraform init

# 3. تعديل main.tf للعودة
resource "local_file" "config" {
  filename = "terraform.txt"
  content  = "This file has been created with Terraform"
}

# 4. تطبيق التغييرات
terraform apply
# → terraform.txt تم إنشاؤه، و opentofu.txt تم حذفه

💡 ملاحظة مهمة

أثناء عملية الترحيل العكسي، قد يكون هناك تباعد (divergence) بين ما تم إنشاؤه بـ OpenTofu وما تتوقعه إعدادات Terraform. في الحالات النادرة، قد تحتاج إلى استعادة النسخة الاحتياطية من الحالة.

⚖️ مقارنة: الترحيل مقابل الترحيل العكسي

🚀 إلى OpenTofu

  1. نسخة احتياطية من terraform.tfstate
  2. تثبيت OpenTofu
  3. tofu init
  4. tofu plan → فحص
  5. اختبار بتغيير صغير
  6. tofu apply → اكتمال الترحيل

↩️ إلى Terraform

  1. نسخة احتياطية من حالة OpenTofu
  2. التأكد من تثبيت Terraform
  3. terraform init
  4. terraform plan → فحص
  5. استعادة التغييرات إن لزم
  6. terraform apply → اكتمال العودة

⚠️ أخطاء شائعة يجب تجنبها

❌ خطأ 1: الترحيل بدون نسخة احتياطية

دائماً أنشئ نسخة احتياطية من ملف الحالة قبل الترحيل. إذا فشلت العملية، يمكنك الاستعادة من النسخة الاحتياطية. 

# ❌ خطر - بدون نسخة احتياطية
tofu init

# ✅ آمن - مع نسخة احتياطية
tar -czf tfstate-backup.tar.gz terraform.tfstate
tofu init

❌ خطأ 2: اختبار الترحيل على موارد حرجة

لا تختبر الترحيل بتغيير موارد حرجة مثل قواعد البيانات أو خوادم الإنتاج. استخدم مورداً بسيطاً مثل ملف محلي أو مورد اختباري.

❌ خطأ 3: نسيان فحص الخطة

بعد tofu init، شغل دائماً tofu plan للتأكد من عدم وجود تغييرات غير متوقعة. إذا ظهرت تغييرات غير متوقعة، لا تكمل الترحيل!

❌ خطأ 4: استخدام إصدارات غير متوافقة

تأكد من أن إصدار Terraform الذي تستخدمه متوافق مع OpenTofu. الإصدار 1.6 هو نقطة التوافق. إذا كنت تستخدم إصداراً أقدم، قم بالترقية أولاً.

🎤 أسئلة مقابلات مهمة

سؤال 1: ما هي خطوات الترحيل من Terraform إلى OpenTofu؟

1. إنشاء نسخة احتياطية من ملف الحالة.
2. تثبيت OpenTofu.
3. تشغيل tofu init لتهيئة المشروع.
4. فحص الخطة بـ tofu plan.
5. اختبار بتغيير صغير غير حرج.
6. تطبيق التغييرات بـ tofu apply.

سؤال 2: ما هو إصدار Terraform المتوافق مع OpenTofu؟

الإصدار 1.6 من Terraform متوافق مع OpenTofu 1.6. إذا كنت تستخدم إصداراً أقدم، يجب الترقية إلى 1.6 أولاً قبل الترحيل.

سؤال 3: لماذا نحتاج إلى نسخة احتياطية قبل الترحيل؟

لأن ملف الحالة يحتوي على جميع معلومات البنية التحتية. إذا فشلت عملية الترحيل أو حدثت مشكلة، يمكن استعادة الحالة من النسخة الاحتياطية والعودة إلى الوضع السابق.

سؤال 4: هل يمكن العودة من OpenTofu إلى Terraform؟

نعم، بنفس السهولة:
1. إنشاء نسخة احتياطية من حالة OpenTofu.
2. تشغيل terraform init.
3. فحص الخطة بـ terraform plan.
4. الاستمرار مع Terraform.
ملاحظة: قد يحدث تباعد (divergence) بين ما تم إنشاؤه بـ OpenTofu وما تتوقعه Terraform.

سؤال 5: أين يمكن الحصول على المساعدة إذا واجهت مشاكل؟

• GitHub Discussions: للأسئلة العامة والنقاشات
