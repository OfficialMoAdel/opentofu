💡 لماذا نهتم بالاعتماديات؟

  • الإنشاء: يحدد ترتيب إنشاء الموارد
  • الحذف: يحدد ترتيب حذف الموارد (عكس الترتيب)
  • الأمان: يمنع الأخطاء الناتجة عن إنشاء مورد قبل اعتماده

🏷️ سمات الموارد (Resource Attributes)

عند إنشاء مورد، يقوم OpenTofu بتسجيل عدة قيم تتعلق بهذا المورد. يمكن عرض هذه السمات باستخدام tofu show.

📄 مثال: AWS Key Pair

resource "aws_key_pair" "alpha" {
  key_name   = "alpha"
  public_key = "ssh-rsa AAAAB3Njvlkdjskdnajdhajs;faf.....alpha@a-server"
}

🔍 عرض السمات المصدرة

tofu show

📋 السمات المصدرة من aws_key_pair

arn - ARN الخاص بالمورد
fingerprint - بصمة المفتاح
id - معرف المورد
key_name - اسم المفتاح
public_key - المفتاح العام
tags_all - جميع الوسوم

✅ الـ Reference Expression

يمكن استخدام السمات المصدرة كمدخلات لموارد أخرى عبر الصيغة: 

# الصيغة العامة
resourceType.resourceName.attribute

# مثال عملي
aws_key_pair.alpha.key_name

🔵 الاعتماد الضمني (Implicit Dependency)

عندما يستخدم مورد سمة من مورد آخر عبر الـ Reference Expression، يفهم OpenTofu الاعتماد تلقائياً.

📄 مثال: EC2 Instance يعتمد على Key Pair

# المورد الأول: إنشاء المفتاح
resource "aws_key_pair" "alpha" {
  key_name   = "alpha"
  public_key = "ssh-rsa AAAAB3Njvlkdjskdnajdhajs;faf.....alpha@a-server"
}

# المورد الثاني: إنشاء الماكينة (تعتمد على المفتاح)
resource "aws_instance" "cerberus" {
  ami           = var.ami
  instance_type = var.instance_type
  key_name      = aws_key_pair.alpha.key_name  # ← Implicit Dependency
}

🔄 ترتيب الإنشاء والحذف

1️⃣ aws_key_pair.alpha

يُنشأ أولاً

←
2️⃣ aws_instance.cerberus

يُنشأ ثانياً

1️⃣ aws_instance.cerberus

يُحذف أولاً

←
2️⃣ aws_key_pair.alpha

يُحذف ثانياً

💡 متى يحدث الاعتماد الضمني؟

عندما تستخدم resourceType.resourceName.attribute داخل مورد آخر. هذا يخبر OpenTofu تلقائياً أن المورد الثاني يعتمد على الأول.

🔴 الاعتماد الصريح (Explicit Dependency)

عندما لا يوجد اعتماد ضمني بين الموارد، ولكنك تريد تحديد ترتيب الإنشاء، استخدم depends_on.

📄 مثال: إنشاء DB قبل Web

# المورد الأول: قاعدة البيانات
resource "aws_instance" "db" {
  ami           = var.db_ami
  instance_type = var.web_instance_type
}

# المورد الثاني: خادم الويب (يعتمد على DB)
resource "aws_instance" "web" {
  ami           = var.web_ami
  instance_type = var.db_instance_type
  depends_on = [
    aws_instance.db  # ← Explicit Dependency
  ]
}

📄 مثال آخر: ملف يعتمد على ملف آخر

# المورد الأول: ملف krill
resource "local_file" "krill" {
  filename = "/root/krill"
  content  = "krill"
}

# المورد الثاني: ملف whale (يعتمد على krill)
resource "local_file" "whale" {
  filename = "/root/whale"
  content  = "whale"
  depends_on = [ local_file.krill ]  # ← Explicit Dependency
}

⚠️ متى تستخدم depends_on؟

  • عندما لا يوجد اعتماد ضمني بين الموارد
  • عندما تريد إنشاء مورد قبل آخر لأسباب منطقية
  • مثال: إنشاء قاعدة البيانات قبل خادم التطبيق

⚖️ مقارنة: ضمني مقابل صريح

المعيار الاعتماد الضمني الاعتماد الصريح
كيف يحدث؟ تلقائياً عبر الـ Reference Expression يدوياً عبر depends_on
مثال key_name = aws_key_pair.alpha.key_name depends_on = [aws_instance.db]
متى تستخدمه؟ عندما يحتاج مورد لسمة من مورد آخر عندما تريد ترتيباً معيناً دون استخدام سمات
الأفضلية ✅ مفضل دائماً ⚠️ استخدمه فقط عند الضرورة

🎤 سؤال مقابلة شائع

Resource A يعتمد على Resource B لكنه لا يستخدم أي من سماته. ما نوع هذا الاعتماد؟
الإجابة: Explicit Dependency - لأنه لا يوجد استخدام للسمات، يجب استخدام depends_on.

🎯 استهداف الموارد (Resource Targeting)

يمكنك استهداف مورد محدد فقط لتطبيق التغييرات عليه دون باقي الموارد.

📄 مثال عملي

# المورد الأول: نص عشوائي
resource "random_string" "server-suffix" {
  length  = 6
  upper   = false
  special = false
}

# المورد الثاني: ماكينة تعتمد على النص العشوائي
resource "aws_instance" "web" {
  ami           = "ami-013356knkd354"
  instance_type = "web ${random_string.server-suffix.id}"
}

🔧 استخدام --target

# استهداف مورد واحد فقط
tofu apply --target random_string.server-suffix

# الصيغة العامة
tofu apply --target resourceType.resourceName

⚠️ تنبيه مهم

استهداف الموارد يجب أن يُستخدم فقط في الحالات النادرة مثل:

  • تصحيح خطأ سريع
  • معالجة تغيير عاجل دون تنفيذ الخطة الكاملة

لا تستخدمه بشكل روتيني! OpenTofu سيحذرك أن التغييرات المطبقة قد تكون غير كاملة.

🎯 أمثلة عملية كاملة من الملف

📄 مثال 1: TLS Private Key → Local File

# key.tf

# المورد الأول: إنشاء مفتاح خاص
resource "tls_private_key" "pvtkey" {
  algorithm = "RSA"
  rsa_bits  = 4096
}

# المورد الثاني: حفظ المفتاح في ملف
resource "local_file" "key_details" {
  filename = "/root/key.txt"
  content  = tls_private_key.pvtkey.private_key_pem  # ← Implicit Dependency
}

📄 مثال 2: Time Static → Local File

# main.tf

# المورد الأول: طابع زمني
resource "time_static" "time_update" {
}

# المورد الثاني: ملف يحتوي على الطابع الزمني
resource "local_file" "time" {
  filename = "/root/time.txt"
  content  = "Time stamp of this file is ${time_static.time_update.id}"
}

✅ السمات المصدرة من time_static

id - المعرف (طابع زمني)
day - اليوم
hour - الساعة
minute - الدقيقة
month - الشهر
second - الثانية
unix - طابع يونكس
year - السنة
rfc3339 - صيغة RFC3339

📤 متغيرات الإخراج مع الاعتماديات

يمكن استخدام متغيرات الإخراج لعرض سمات الموارد بعد إنشائها. 

# المورد
resource "aws_instance" "cerberus" {
  ami           = var.ami
  instance_type = var.instance_type
}

# متغير الإخراج
output "pub_ip" {
  value       = aws_instance.cerberus.public_ip
  description = "print the public IPv4 address"
}

🔧 الأوامر المفيدة

# عرض جميع متغيرات الإخراج
tofu output

# عرض متغير إخراج محدد
tofu output pub_ip

⚠️ أخطاء شائعة يجب تجنبها

❌ خطأ 1: نسيان القوس المربع في depends_on

# ❌ خطأ
depends_on = aws_instance.db

# ✅ صحيح
depends_on = [ aws_instance.db ]

❌ خطأ 2: استخدام depends_on عندما يوجد اعتماد ضمني

إذا كنت تستخدم سمة من مورد آخر، فلا تحتاج إلى depends_on. الـ Reference Expression يكفي لإنشاء الاعتماد الضمني.

❌ خطأ 3: الإفراط في استخدام --target

استهداف الموارد يجب أن يكون نادراً. الاستخدام المفرط يمكن أن يؤدي إلى حالة غير متسقة.

🎤 أسئلة مقابلات مهمة

سؤال 1: ما الفرق بين الاعتماد الضمني والصريح؟

الاعتماد الضمني: يحدث تلقائياً عندما يستخدم مورد سمة من مورد آخر عبر الـ Reference Expression.
الاعتماد الصريح: يُحدد يدوياً باستخدام depends_on عندما لا يوجد استخدام للسمات.

سؤال 2: ما هي صيغة الـ Reference Expression؟

resourceType.resourceName.attribute
مثال: aws_key_pair.alpha.key_name

سؤال 3: ما هو ترتيب الإنشاء والحذف عند وجود اعتماد؟

الإنشاء: المورد المعتمد عليه أولاً، ثم المورد المعتمد.
الحذف: المورد المعتمد أولاً، ثم المورد المعتمد عليه (عكس الترتيب).

سؤال 4: متى تستخدم --target؟

فقط في الحالات النادرة مثل تصحيح خطأ سريع أو معالجة تغيير عاجل. لا يُنصح باستخدامه بشكل روتيني لأنه قد يؤدي إلى حالة غير متسقة.

⚡ مرجع سريع

المفهوم الصيغة متى تستخدمه
Reference Expression resourceType.resourceName.attribute عندما يحتاج مورد لسمة من مورد آخر
Implicit Dependency key_name = aws_key_pair.alpha.key_name تلقائياً عبر الـ Reference Expression
Explicit Dependency depends_on = [aws_instance.db] عندما لا يوجد استخدام للسمات
Resource Targeting tofu apply --target resourceType.resourceName في الحالات النادرة فقط
Output Variable output "name" { value = ... } لعرض سمات الموارد بعد الإنشاء
