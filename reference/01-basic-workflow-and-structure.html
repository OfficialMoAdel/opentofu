📋 دورة العمل الأساسية (Basic Workflow)

هذه هي الخطوات الأساسية التي ستستخدمها في كل مرة تعمل فيها مع OpenTofu. احفظها جيداً!

1

Initialize

tofu init

يقوم بتنزيل الـ Providers المطلوبة وتجهيز مجلد العمل

2

Plan

tofu plan

يعرض ما سيفعله دون تنفيذه (مثل Dry Run)

3

Apply

tofu apply

ينفذ التغييرات فعلياً على البنية التحتية

4

Show

tofu show

يعرض حالة البنية التحتية الحالية

5

Destroy

tofu destroy

يحذف جميع الموارد التي تم إنشاؤها

💡 نصيحة للمقابلات

لماذا نستخدم tofu plan قبل tofu apply؟
لأنه يعرض لك ما سيحدث دون تنفيذه، مما يسمح لك بمراجعة التغييرات وتجنب الأخطاء. هذا مهم جداً في بيئات الإنتاج (Production).

📝 أوامر إضافية مفيدة

الأمر الوظيفة متى تستخدمه
tofu apply -auto-approve تنفيذ بدون طلب تأكيد في الاختبارات فقط، ليس في الإنتاج
tofu destroy -auto-approve حذف بدون طلب تأكيد عند التنظيف السريع
tofu validate التحقق من صحة الـ syntax قبل أي أمر آخر
tofu fmt تنسيق الكود بشكل قياسي قبل رفع الكود إلى GitHub

📁 هيكل الملفات المثالي (File Structure)

تقسيم الكود إلى ملفات منفصلة يجعل المشروع أسهل في القراءة والصيانة. هذا سؤال شائع في المقابلات!

📄 main.tf

يحتوي على تعريف الـ Resources (البنية التحتية الفعلية)

أساسي

📄 variables.tf

يحتوي على تعريف المتغيرات (المدخلات)

أساسي

📄 outputs.tf

يحتوي على المخرجات التي تريد عرضها

اختياري

📄 provider.tf

يحتوي على إعدادات الـ Provider (مثل AWS أو Azure)

أساسي

💡 لماذا نقسم الكود إلى ملفات منفصلة؟

  • القراءة: يسهل على أي شخص فهم المشروع
  • الصيانة: التعديل على جزء واحد دون التأثير على الباقي
  • إعادة الاستخدام: يمكن استخدام نفس الـ variables في مشاريع أخرى

🎯 أول مثال عملي: إنشاء ملف محلي

هذا هو أبسط مثال لتفهم كيف يعمل OpenTofu. سننشئ ملف نصي محلي باستخدام الـ local provider.

📄 main.tf

# إنشاء ملف نصي محلي
resource "local_file" "pet" {
  filename = "/root/pets.txt"
  content  = "we love pets"
  file_permation = "0700"
}

🔧 خطوات التنفيذ

# 1. تهيئة المشروع (تنزيل الـ local provider)
tofu init

# 2. عرض ما سيحدث (اختياري لكن مستحسن)
tofu plan

# 3. تنفيذ التغييرات
tofu apply

# 4. عرض النتيجة
tofu show

# 5. حذف كل شيء (عند الانتهاء)
tofu destroy

⚠️ تنبيه مهم

في الملف الأصلي كان هناك خطأ إملائي: file_permation
الصحيح هو: file_permission
استخدم tofu validate دائماً لاكتشاف مثل هذه الأخطاء!

🧠 مفاهيم أساسية يجب حفظها

📌 Resource Block Syntax

resource "<resource_type>" "<resource_name>" {
  argument1 = "value1"
  argument2 = "value2"
}
المصطلح الشرح مثال
resource الكلمة المفتاحية لتعريف مورد جديد resource
resource_type نوع المورد (يتبع للـ Provider) local_file, aws_instance
resource_name اسم منطقي تختاره أنت للمورد "pet", "webserver"
arguments خصائص وإعدادات المورد filename, content

💡 سؤال مقابلة شائع

ما الفرق بين resource و data source؟
• resource: يستخدم لإنشاء وإدارة البنية التحتية (يكتب)
• data source: يستخدم لقراءة معلومات من بنية موجودة مسبقاً (يقرأ فقط)

💾 ملف الحالة (State File)

بعد أول tofu apply، سيتم إنشاء ملف الحالة تلقائياً. 

# اسم ملف الحالة الافتراضي
terraform.tfstate

# ملف النسخ الاحتياطي
terraform.tfstate.backup

💡 نقاط مهمة عن الـ State

  • يحتوي على جميع معلومات البنية التحتية بصيغة JSON
  • هو "مصدر الحقيقة" (Source of Truth) لـ OpenTofu
  • لا تضعه أبداً في Git (يحتوي معلومات حساسة)
  • استخدم tofu show لعرض محتواه

⚡ مرجع سريع للأوامر

# دورة العمل الكاملة
tofu init          # تهيئة
tofu validate      # التحقق من الصحة
tofu plan          # عرض الخطة
tofu apply         # التنفيذ
tofu show          # عرض الحالة
tofu destroy       # الحذف

# أوامر مفيدة
tofu fmt           # تنسيق الكود
tofu output        # عرض المخرجات
tofu state list    # عرض الموارد في الـ state
